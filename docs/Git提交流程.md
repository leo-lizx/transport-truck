# Git 提交与推送流程

> 版本 v1.1；建立 2026-10-19；适用仓库：`transport-truck`。
> 依据：HecateFlow 的 Git discipline（`HF-AUTH-001`、`HF-GIT-001`、`HF-GIT-PROFILE-001`）
> 与本工程 [.hecateflow/project.json](../.hecateflow/project.json) 的 `git` 段。
> 本文是用户与 AI 助手之间的提交契约：用户说“提交”时，助手按第 4 节自主完成；
> 本文不包含推送授权。

## 1. 授权与触发

| 用户说法 | 授权范围 | 助手行为 |
|----------|----------|----------|
| “提交”“提交这些改动”“commit” | 对当前工作区的改动做**本地**提交 | 按第 4 节自主分组、验证、提交并汇报，不再逐条询问 |
| “推送”“push” | 推送到 `origin/transport-local` | 推送前单独确认远端、分支和范围 |
| 未提及 | 只做代码/文档改动与构建、测试 | 不暂存、不提交 |

- 提交只落在 `transport-local`；`main` 只作上游对照。
- 删除用户资料、改写历史、修改远端、创建/删除分支：无论何时都单独确认。

## 2. 命名规范（溯源用）

### 2.1 标题

格式：`{模块} {动作}{对象}`，中文、不超过 50 字、句尾不加句号、不使用 emoji。

**模块词表**（只从这里选，便于按前缀检索）：

```text
工程文档 / 吸盘测试 / 底盘控制 / 底盘PID / 视觉 / 构建工程 / 工程流程 / 测试
```

**动作词表**：

```text
新增 / 修复 / 重构 / 同步 / 清理 / 补齐 / 更新 / 移除 / 调整 / 回滚
```

**对象**写具体文件、功能或模式，不写“一些”“相关”“若干”“部分”。

### 2.2 正文

正文固定五段，每段一行，便于 `git log --grep` 与人工溯源：

```text
背景：为什么要改
改动：改了哪些文件或行为
验证：执行了什么命令、结果如何
风险：未验证项或影响面
关联：文档路径、任务编号（如 Q-07）或前序提交哈希
```

其中“风险”没有内容时写“无”，不要省略。

### 2.3 格式示例（示意，非历史提交原文）

```text
底盘PID 修复调试打印空表达式告警

背景：DEBUG_UART_ENABLE=0 时 printf 被展开为 (0)，IAR 报 Pe174。
改动：chassis_pid.c 的 printf 宏改为 ((void)0)，与 main.c 写法一致。
验证：IAR nor_sdram_zf_dtcm 重建 0 error 0 warning；MDK 增量 0 error。
风险：未上电验证，仅影响调试输出。
关联：docs/Git提交流程.md
```

### 2.4 检索与追溯

```bash
git log --oneline --grep '^吸盘测试'            # 按模块前缀
git log --oneline --grep '关联：Q-07'           # 按任务编号
git log --oneline --follow -- docs/PINOUT.md    # 按文件追踪
git show <哈希>                                  # 查看单次改动与验证记录
```

## 3. 提交前验证

| 检查 | 命令 | 通过标准 |
|------|------|----------|
| IAR 编译 | `iarbuild project/iar/program/rt1064.ewp -build nor_sdram_zf_dtcm` | `Build succeeded`，0 error |
| MDK 编译 | `UV4.exe -r project/mdk/rt1064.uvprojx -j0 -o <log>` | 0 error；warning 须说明来源 |
| 主机行为测试 | 见 [tests/suction/README.md](../tests/suction/README.md) | `0 failures` |
| 文档链接 | 扫描 Markdown 相对链接 | 0 个缺失目标 |

按改动风险选择，不要求每次全跑；未执行的项在“验证”段写明“未跑”，不能默认通过。

## 4. 助手自动执行流程

收到“提交”后，助手按以下顺序自主完成，中途不再逐条确认：

1. **记录基线**：`git status --short`、`git diff --stat`，确认哪些是本次改动。
2. **按模块分组**：同一目的的文件归一组（代码与其必需的构建登记、测试、文档可同组）。
3. **逐组验证**：按第 3 节选择检查；失败先修复，不提交失败状态。
4. **只暂存本组**：`git add -- <文件…>`，`git diff --cached` 逐行复核；禁止 add-all。
5. **按第 2 节格式提交**，一组一个提交。
6. **收尾检查**：`git status --short` 应只剩不入库资料（第 6 节）。
7. **汇报**：输出下表，并说明未推送。

汇报表格式：

| 哈希 | 标题 | 文件 | 验证 | 未覆盖 |
|------|------|------|------|--------|
| `abc1234` | 吸盘测试 新增模式4 | 12 | IAR/MDK/主机测试 | 未烧录 |

遇到以下情况先停下来询问：改动无法归类、要删除用户资料、要改历史或远端、验证失败且原因不明。

## 5. 拆分规则

| 场景 | 拆法 |
|------|------|
| 新功能 | 代码 + 测试 + 构建登记一个提交；配套文档可同提交 |
| 修缺陷 | 修复一个提交；同次发现的其他问题另开提交 |
| 纯文档 | 一个提交，正文注明“仅文档变更” |
| 构建配置 | 单独一个提交，写清验证命令与结果 |
| 行尾/格式归一 | 不单独制造大范围 diff；随相关文件提交并在正文说明 |

## 6. 不入库的本地资料

以下已在 [.gitignore](../.gitignore) 中忽略，只保留在本地：

- `【原理图】…`、`【文档】…`、`【软件】…` 三个参考资料目录（约 75 MB）；

- MDK 的 `project/mdk/Objects/`、`project/mdk/Listings/`，以及 IAR 构建产物。

仓库只保留源码、工程文件、项目文档和必要的实物标注图（如 `docs/hardware/`）。

## 7. 提交前检查清单

- [ ] `git status --short` 中只有本次改动的文件
- [ ] `git diff --cached` 逐行看过，无调试输出、临时文件、无关重排
- [ ] IAR 编译 0 error（涉及固件时）
- [ ] MDK 编译 0 error（涉及工程/构建时）
- [ ] 主机行为测试通过（涉及算法、状态机时）
- [ ] 文档相对链接可解析
- [ ] 标题符合模块/动作词表，正文五段齐全
- [ ] 没有推送、没有改远端（除非任务明确要求）

## 8. 提交信息模板

仓库根目录的 [.gitmessage](../.gitmessage) 是提交信息模板。新克隆后执行一次：

```bash
git config commit.template .gitmessage
```

之后手动 `git commit` 会带出格式提示（以 `#` 开头的提示行不会进入提交内容）。
