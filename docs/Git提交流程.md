# Git 提交流程

> 建立日期：2026-10-19；适用仓库：`transport-truck`。
> 依据：HecateFlow 的 Git discipline（`HF-AUTH-001`、`HF-GIT-001`、`HF-GIT-PROFILE-001`）与本工程
> [.hecateflow/project.json](../.hecateflow/project.json) 的 `git` 段（`commitFormat`、`neverAddAll`）。
> 目标：每次改动都有可追溯的提交，便于定位问题、回退和交接。

## 1. 授权边界

| 操作 | 是否需要单独确认 |
|------|------------------|
| 读文件、编译、跑测试 | 否 |
| 暂存、提交 | 需要当次任务明确；本文只规定做法，不代替单次授权 |
| 推送到 `origin` | 需要，默认只提交不推送 |
| 改远端、改历史、建删分支 | 需要，默认不做 |

代码写入权限不等于 Git 写入权限；`git commit` 也不等于允许推送。

## 2. 分支

| 分支 | 用途 |
|------|------|
| `main` | 上游镜像（`origin/main`），只用于对照 |
| `transport-local` | 本地开发分支（当前工作分支），提交先落在这里 |

## 3. 一次改动的标准流程

### 3.1 开始前记录基线

```bash
git status --short
git diff --stat
```

任务开始前已有的未提交改动属于历史工作：要么单独拆成提交，要么保持未暂存，**不混进本次提交**。

### 3.2 改动后按风险验证

| 检查 | 命令 | 通过标准 |
|------|------|----------|
| IAR 编译 | `iarbuild project/iar/program/rt1064.ewp -build nor_sdram_zf_dtcm` | `Build succeeded`，0 error |
| MDK 编译 | `UV4.exe -r project/mdk/rt1064.uvprojx -j0 -o <log>` | 0 error；warning 须说明来源 |
| 主机行为测试 | 见 [tests/suction/README.md](../tests/suction/README.md) | `0 failures` |
| 文档链接 | 扫描 Markdown 相对链接 | 0 个缺失目标 |

未执行的验证必须在提交正文中写明，不能默认通过。

### 3.3 只暂存本次文件

```bash
git add -- 文件1 文件2 目录/
git diff --cached --stat
git diff --cached
```

禁止 `git add -A`、`git add .`、`git commit -a`。逐行看一遍暂存内容，确认没有构建产物、临时文件、调试输出或无关改动。

### 3.4 提交

```bash
git commit -m "{模块} {动作/说明}" -m "为什么改、怎么验证、哪些没验证"
```

### 3.5 提交后确认

```bash
git log --oneline -3
git status --short
```

`git status` 应只剩不入库的本地资料（见第 6 节）；把提交哈希记入交接文档或本次任务说明。

## 4. 提交消息规范

- 标题：`{模块} {动作/说明}`，中文、不超过 50 字、句尾不加句号。
- 模块取功能或目录名：`工程文档`、`吸盘测试`、`底盘PID`、`底盘控制`、`构建工程`、`工程流程`。
- 正文必须写清三件事：改了什么、为什么、怎么验证；有未覆盖风险时一并写明。
- 一个提交只解决一个问题；为新功能必需的构建登记、测试和文档可以放在同一个提交。
- 禁止无信息标题：`update`、`fix`、`修改`、`提交`、`临时提交`。

本仓库已使用的示例：

```text
工程文档 清理底盘评审中的失效引用
工程文档 同步工程精简与吸盘模式4说明
吸盘测试 新增模式4并精简主入口
构建工程 补齐MDK底盘源文件登记
底盘PID 修正调试打印的空表达式告警
```

## 5. 怎么拆分提交

| 场景 | 拆法 |
|------|------|
| 新功能 | 代码 + 测试 + 构建登记一个提交；配套文档可同提交 |
| 修缺陷 | 修复一个提交；同次发现的其他问题另开提交 |
| 纯文档 | 一个提交，正文注明“未改代码” |
| 构建配置 | 单独一个提交，写清验证命令与结果 |
| 行尾/格式归一 | 不单独制造大范围 diff；随相关文件一起提交并在正文说明 |

## 7. 提交前检查清单

- [ ] `git status --short` 中只有本次改动的文件
- [ ] `git diff --cached` 逐行看过，无调试输出、临时文件、无关重排
- [ ] IAR 编译 0 error（涉及固件时）
- [ ] MDK 编译 0 error（涉及工程/构建时）
- [ ] 主机行为测试通过（涉及算法、状态机时）
- [ ] 文档相对链接可解析
- [ ] 提交消息符合第 4 节，正文包含验证结果和未覆盖风险
- [ ] 没有推送、没有改远端（除非任务明确要求）
