## ★ 整车流程验证器 (`sokoban_car_sim.py`)

这是按用户要求**重新制作**的验证器：UI 与**车上屏幕 (`chassis_menu.c` / IPS200)
完全一致**（黑底、灰格线、墙=深蓝灰、目标=品红、箱子=橄榄绿、炸弹=红、车=青色、
右侧 LEGEND 图例、底部状态行），运动流程**严格复刻固件 `app_game_logic.c` 的整车
状态机**：

| 阶段 | 对应固件 Stage | 行为 |
|---|---|---|
| 发车 | `STAGE_WAIT_START` | 回唯一库位 `(1,5)` → 右移至地图刷新触发格 `(2,5)` |
| 识别 | `STAGE_RECOGNIZE_MAP` | 第 2/3 关通常实地分类；第 2 关连续共线目标走盲扫特判；第 1 关跳过 |
| 规划 | `STAGE_PLAN_PATH` | 第1关连续计时时间优化 / 第2关按数字配对 / 第3关含炸弹 |
| 执行 | `STAGE_EXECUTE_ACTION` | 推箱；**第 3 关先把炸弹推入墙体 3×3 爆破开路**再推箱 |
| 判定 / 完成 | `STAGE_LEVEL_JUDGE` / `STAGE_DONE` | 全部到位后忽略虚拟障碍，直线返库 |

**按数字配对（第 2/3 关）**：目标点带数字图案，箱子必须推到**与自己号码相同**的目标。
通常需要实地走到**每一个**箱子和目标前观察；第二关若至少 3 个目标连续共行或共列，主控跳过图案识别，只依据开局地图一次性规划所有箱子，再连续扫过整条目标线；箱间不重读地图，全部执行完后才统一复核。单箱搜索直接以“到达目标线外入口且最后一推朝向目标线”为终态，保留地图中的真实墙、箱子和目标，不再添加入口虚拟墙。箱子已在入口时只规划车辆走到箱后；箱子位于目标排延长线上且通道畅通时直接沿同轴推入。重复号码按出现次数逐个命中。
整车图形验证器会同步显示该分支：`RECOGNIZE` 不产生观察转向，`PLAN` 标记“1 次读图 / 1 个执行批次”，扫描中命中同号目标时箱子与目标同时消失。

特性：
- **自定义地图**：内置编辑器，`# - . $ * @` 格式（与主控 `app_link.c` 一致）。
- **自动生成符合要求的地图**：玩家强制从左库位起步、预留 `(1,5)→(2,5)` 发车走廊，求解器校验可解。
  - 第 2 关：内墙更密、目标号码为**非恒等排列**，保证"必须按数字配对"才解得开。
  - 第 3 关：所有目标在识别阶段均可到达观察；内墙挡在推箱通道上，需先推炸弹炸开再按号配对。
- 播放 / 暂停 / 单帧步进 / 复位 / 调速，逐格回放与车一致的网格运动。
- 算法层 100% 复用 `sokoban_validator.py`（= `algo_sokoban_solver.c` 的 PC 镜像）。

## 功能

| 功能 | 说明 |
|------|------|
| **Stage1** | 推宏 A* + 箱序/目标配对时间搜索，计入航点停站、关键 Snap 和直线返库 |
| **Stage2** | 通常按识别映射推箱；连续共线目标改用单快照全量规划与连续盲扫 |
| **Stage3** | 炸弹推入墙体、**3×3 炸墙**、再推剩余箱子；含侦查 |
| **随机地图** | 可调箱子数、内墙密度、随机种子 |
| **导入/导出** | ASCII 地图：`# - $ . * @`（与主控 `app_link.c` 一致） |
| **指令验证** | 粘贴 `SCOUT` / `PUSH` / `BOMB` 段，模拟并判定通关 |

## 地图格式（12 行 × 16 列）

```
################
#---@---$------#
#......$......#
...
```

- `#` 墙  `-` 空地  `.` 目标  `$` 箱子  `*` 炸弹  `@` 玩家起点

## 运行指令格式

```text
# 侦查（Stage2/3 必访所有箱子侧面观察点）
SCOUT: W7,5;W9,4
# 或方向串（仅小写行走）
SCOUT: rrrd

# 推炸弹（Stage3）
BOMB: rrrdL

# 推箱（小写走 大写推）
PUSH: rrrUdddLL
```

路点写法：`W列,行` 或 `W列 行`，多个用 `;` 或空格分隔。
